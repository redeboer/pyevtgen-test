Python bindings for [EvtGen](https://gitlab.cern.ch/evtgen/evtgen), the Monte Carlo generator for particle decays, in particular weak decays of heavy-flavor hadrons.

The wheels are self-contained: EvtGen 3.1.0, HepMC 3.3.1 and Pythia 8.318 are compiled statically into the extension module, and the package ships EvtGen's default decay table (`DECAY.DEC`), its particle table (`evt.pdl`) and the Pythia8 data that the `PYTHIA` decay model needs. No ROOT installation or environment variables are required.

> [!NOTE]
> This is an unofficial package that is not maintained by the EvtGen authors.

## Installation

```shell
pip install pyevtgen
```

Wheels are built for Linux (x86_64, aarch64) and macOS (arm64, x86_64) for Python 3.10 and newer.

## Usage

```python
from pyevtgen import Generator, final_state_momenta

generator = Generator(seed=42)
event = generator.decay("B0")
for particle in event.final_state():
    print(particle.name, particle.pdg_id, particle.p4)
```

A `Particle` holds its EvtGen name, PDG ID, lab-frame four-momentum `p4` as (E, px, py, pz) in GeV, production `position` as (ct, x, y, z) in mm, and its `daughters`. Pass `p4=` to `decay()` or `generate()` to boost the parent; by default it decays at rest.

To study a single channel, override the default decay table with a user decay file and stack the events into a NumPy array of shape `(n_events, n_final_state, 4)`:

```python
generator = Generator(user_decay_file="D0_Kpipi0.dec", seed=0)
events = generator.generate("D0", n=10_000)
momenta = final_state_momenta(events)
```

Particle properties from the particle table are available by name or PDG ID:

```python
generator.properties("J/psi").mass
generator.properties(443).width
```

Final-state radiation can be simulated with Vincia's QED shower from Pythia8 by passing `fsr=True`. It applies to decay channels that carry the `FSR` (or legacy `PHOTOS`) flag in the decay file. PHOTOS++, Tauola++ and Sherpa are not included.

### Limitations

EvtGen stores its particle table, decay table and random engine in global state, so a process can create only one `Generator`. Reuse it, or call `read_user_decay_file()` to load additional decay files. EvtGen terminates the process on a malformed decay file, which Python cannot catch as an exception.

## Development

The project builds with [scikit-build-core](https://scikit-build-core.readthedocs.io) and [nanobind](https://nanobind.readthedocs.io). CMake downloads the pinned EvtGen, HepMC3 and Pythia8 sources on the first build, so building from source requires network access and a C++17 compiler.

[Pixi](https://pixi.sh) provides the compilers, CMake, Ninja and uv, while [uv](https://docs.astral.sh/uv) manages the Python environment in `.venv`. With [direnv](https://direnv.net), the `.envrc` file activates both when you enter the repository.

```shell
pixi run test     # build the package and run the tests
pixi run style    # formatters and linters
pixi run build    # source distribution and wheel in dist/
pixi run upgrade  # upgrade lock files and pre-commit hooks
```

uv rebuilds the extension automatically when C++ or CMake sources change. You can also use uv directly with a system C++17 compiler, for instance `uv run pytest`.

The VS Code workspace recommends extensions for the Python and C++ tooling. For C++, [clangd](https://clangd.llvm.org) reads `build/compile_commands.json`, which the first local build creates. `src/pyevtgen/_core.pyi` is generated by nanobind on every build and committed, so that type checkers can resolve the extension module.

To update a dependency, change its version and SHA256 hash in `CMakeLists.txt`.

## Releases

Publishing a GitHub release triggers the `wheels.yml` workflow, which builds the source distribution and wheels with [cibuildwheel](https://cibuildwheel.pypa.io) and uploads them to PyPI through [trusted publishing](https://docs.pypi.org/trusted-publishers). The version is derived from the Git tag. Before the first release, register a pending trusted publisher for the `pyevtgen` project on PyPI with workflow `wheels.yml` and environment `PyPI`, and create that environment in the GitHub repository settings.
